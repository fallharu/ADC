# 分析相談の3担当

| 名前 | 担当 | 主に編集するもの |
| --- | --- | --- |
| `adc_analysis_advisor` | 仮説、誤差分析、改善案、最小比較実験、採否判断の提案 | 対象実験ノート、試験コード、実験manifest |
| `adc_obsidian_curator_lead` | **GPT-6 Sol / medium固定**。整理作業の指示作成と、Lunaの作業結果の統合 | 編集しない。作業指示とまとめを親へ返す |
| `adc_obsidian_curator` | **GPT-6 Luna**。effortはhighを既定とし、依頼ごとに変更可。3Vaultの振り分け、短い要約と索引、ID・根拠リンク、stale整理 | leadと親が指定した索引・出力カタログ |
| `adc_slide_author` | 中間発表の構成、図表説明、1枚ごとの主張と根拠、資料作成 | 対象実験のslide-card、発表原稿・生成コード |

親エージェントが依頼の窓口となり、相談結果を統合する。整理依頼では、GPT-6 Sol medium固定のleadが指示と最終要約を担当する。GPT-6 LunaのcuratorがVaultの実作業を担当し、effortは親が通常highで指定するが、依頼ごとに変更できる。分析・スライド担当はモデルと推論強度を親から引き継ぐ。

## 相談の頼み方

- 「分析担当に、速度推定の改善案を相談して」
- 「整理担当に、今回の実験をObsidianへ整理してもらって」
- 「スライド担当に、このrun IDの結果から中間発表の構成を作ってもらって」
- 「3人に相談して、分析の改善と発表準備の進め方をまとめて」

必要な担当だけ呼ぶ。3人への相談が依頼されたら3担当へ分担し、根拠を照合してまとめる。通常の小さな修正で毎回3人を起動しない。

整理依頼は親が次の順に進行する。

1. `adc_obsidian_curator_lead`（GPT-6 Sol / medium固定）に、依頼・対象ID・最小根拠・制約を渡し、実作業向けの指示を作る。
2. 指示と編集可能ファイルを `adc_obsidian_curator`（GPT-6 Luna、effortは通常high）に渡してVaultを更新させる。依頼に応じて親がeffortを変更してよい。
3. Lunaの報告と変更ファイルを同じleadに渡し、根拠ID・変更・不確実性・残課題をまとめる。
4. 親が最終確認して利用者へ返す。

Sol leadは指示・まとめ専任でVaultを編集しない。Luna curatorは指定された作業だけを行い、再委任しない。親が各段階を順番に進め、同一ノートを同時編集しない。

## 引継ぎ契約

親は「依頼・対象run_id/note_id・最小の根拠・制約・編集可能なファイル・期待する出力」を渡す。会話全文や全Vaultは複製しない。

担当は原則1,200文字以内で「結論／根拠ID／不確実性／次の作業／変更ファイル」を返す。他担当への質問は親を通じて該当担当へ渡し、回答を1回照合する。未解決の意見差は、優劣を装わず検証条件として残す。

独立した読取り・提案は並行できる。同じノート・manifestの同時編集は禁止する。分析担当の結果確定 → スライド担当の根拠整理 → 整理担当の索引更新を基本とする。親が編集担当を切り替えるまで他の担当は当該ファイルを書かない。各担当から再委任しない。

## 設定と利用確認

リポジトリの `.codex/agents/adc_*.toml` がプロジェクト用の役割定義。整理用leadは `gpt-6-sol` / `medium` を固定。実作業担当は `gpt-6-luna` を指定し、effortは固定せず、親が通常 `high` を指定して依頼ごとに変更できる。

参照仕様：[OpenAI公式Codexサブエージェント仕様](https://developers.openai.com/codex/multi-agent/)。カスタムエージェントのTOMLで `model` と `model_reasoning_effort` を指定できる。モデル指定は新しい作業セッションから有効になる。

この環境の `codex --version` は `0.36.0`。この旧CLIでカスタム役割とモデル指定が実際に読み込まれるかは未確認。対応するCodexクライアントでプロジェクトを開き直し、leadとcuratorの役割・モデル設定が反映されたことを利用前に確認する。TOML保存だけではエージェントは起動しない。
