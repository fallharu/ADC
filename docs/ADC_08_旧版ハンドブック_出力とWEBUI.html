01

全体像 — 動画1本が何に変わるか

旧版は「動画 → YOLO推論 → 後処理8ステップ → SQLite → 各種エクスポート」という一方向のパイプラインです。UI 上の操作はすべてこのパイプラインのどこかを叩いているだけで、計算結果は必ず SQLite の Detection テーブルに書き戻されます。画面で見えている数字も、CSV も、Excel も、出どころは同じ1テーブルという構造です。

INPUT動画mp4 / uploads 配下
YOLO推論車両モデル＋タイヤモデル
P1グループIDtrack → group 集約
P2運動学速度・加速度・進行方向
P3白線距離左右白線までの水平距離
P4追い越し判定＋±30f窓
P5区間速度XY区間速度
P6接近／離隔approach / clearance
P7車両間距離ProximityData
P8TTC衝突余裕時間
OUTPUTDB / CSV / 画像Excel・注釈動画

後処理の実体は Source_code/modules/inference.py の run_postprocess_pipeline_sync()。8ステップを順に実行し、成功したステップ名を「後処理を即時実行 (グループID → 運動学 → …)」の形でログに残します。途中で失敗しても残りは続行し、エラー内容が Run ごとに記録されます。

04

WEB UI — 画面構成

起動は run.bat（中身は python -m Source_code.app）。Flask 開発サーバが立ち上がるので、ブラウザで http://127.0.0.1:5000/ を開きます。起動時にDBスキーマの自動マイグレーションが走り、コンソールに登録ルート一覧が出力されます。

画面は左サイドバーの3グループに整理されています。上から順に使えばワークフローが完結する構成です。

05

標準の操作手順

  1. 動画を登録する — 1. 動画登録

    動画ファイルを直接アップロードするか、既存フォルダをリンク登録します。uploads/ 配下に配置され、Video テーブルに FPS・尺・元パスが記録されます。フォルダ単位で一括処理する場合はここでフォルダを登録しておきます。

  2. 推論を回す — 2. YOLO推論

    単一動画モードとフォルダ一括モードがあります。指定する項目は次のとおりです。

    • 年度／場所／道路種別 — 道路種別は「拡幅／未拡幅」から選択。後の比較分析の軸になるので、ここで正しく入れておくのが重要です。
    • 車両検出モデル / タイヤ検出モデル — それぞれ自動（Auto）か明示指定。2モデルを併用します。
    • キャリブレーションプロファイル — 未指定ならサブフォルダ設定が使われます。
    • 処理完了後に後処理を自動実行する — ONにすると推論直後に8ステップが走ります。
    • 処理完了後にCSVを出力する — Run ごとの CSV とフォルダ結合 CSV を自動生成。
    • 既存の実行結果を上書きする — 過去データを削除して再実行。取り消せません。

    進捗は同じ画面のプログレス表示（/progress, /api/batch_status）で追えます。バックグラウンドスレッド実行なので、画面を離れても処理は続きます。

  3. キャリブレーションを当てて再計算する — 3. 後処理

    推論結果は座標のままなので、スケールを与えて初めて m / km/h になります。この画面で対象を Run単位 / フォルダ単位 / 条件指定 / 全データ の4通りから選び、プロファイルを適用して後処理を回します。

    アクションボタンは実行系と出力系が並んでいます。

    • 選択分実行／全データ処理実行 — 後処理8ステップの再計算
    • 動画生成 — 注釈付き動画。フォント・出力形式（avi/mov/mkv）などを指定可能
    • DBそのままCSV / DBそのままExcel — Run 単位のフルダンプ
    • 追い越しペアCSV／自転車・対象車 CSV / Excel — 絞り込み出力

    条件指定モードでは「未拡幅道路 / 拡幅道路 / 未定義」で対象を絞れます。画面下部に解析実行ログが出るので、失敗した Run はここで特定します。

  4. 結果を確認する — 4. 検出結果

    フォルダ別のサマリ（Run数・車・自転車・追い越し件数）と、Run 一覧（Run ID・動画ファイル・検出数・収集年・道路タイプ・処理日時）が並びます。ここから年度や道路種別のメタデータを一括更新でき、行を選んで CSV / Excel を落とせます。検出行のプレビュー画像も参照できます。

  5. 目視で確かめる — Review グループ

    • 追い越し写真 — overtake_snapshots/ の PNG を一覧表示。誤検出はここで削除、あるいは中央線・白線越えのステータスを手で修正します。写真の再生成もこの画面から実行できます。
    • 手動判定 — フレームを送りながら追い越し側／追い越され側を指定して ManualOvertakeEvents に登録。前後30フレームの速度（−30f / +30f）まで含めて保存されるので、自動判定が取りこぼした事例を補完できます。
    • イベント観覧 — 登録済みイベントを表形式で確認し、CSV に出します。
    • 検証 — キャリブレーションの妥当性を距離テストで確認します。

  6. 集計する — 集計

    対象 Run を複数選び、4つの集計モードから選択します。

    • 白線区分モード（A/B比較）／白線距離モード（自転車ID別）
    • 離隔距離×速度モード／トラックID別 速度・白線距離モード
    • 「下向き移動のみ抽出」で進行方向を絞り込み

    画面上に集計値とグラフが出て、そのまま Excel（概要／Run別集計／詳細データ／グラフ の4シート）に落とせます。

  7. 比較する — 比較分析

    年度・道路種別などで群を分け、統計的に比較します。正規性検定を経て検定手法を選び、効果量（Cohen's d / η²）まで算出します。「外れ値を除去する (IQR法)」のチェックで四分位範囲による除外を切り替えられます。

    結果は画面のグラフ（指標を切り替え可能）と Excel レポートで確認できます。Excel は 分析用データ／基本統計量／検定結果／DB_ProcessLog／DB_OvertakeEvents／DB_Video の6シート構成で、元データまで同梱されます。

    「AI分析レポート (Gemini)」ボタンで、集計結果の解説文を生成できます。外部APIキーが必要な機能です。

  8. 配布用に出す — 出力

    §03 の6メニューから目的のファイルをダウンロードします。受け渡しが決まっている場合は「金岡出力」、自前で再分析する場合は「DBそのまま」が基本です。

06

旧版の癖・引き継ぎ時の注意

データを読む前に確認すること
  • キャリブレーション未適用の Run では m / km/h が意味を持ちません。 px 系の列だけが有効です。プロファイル適用後に後処理を回し直す必要があります。
  • speed_km_h が 0 の行が実データに存在します。 スケール未設定や平滑化区間の端で発生します。速度を条件に使う集計では 0 行の扱いを明示してください。
  • OvertakeEvents の距離列が NULL の行があります。 イベント自体は検出されていても、離隔・接近の再計算が回っていないケースです。件数集計と距離集計で母数が変わります。
  • 離隔距離は m / cm / px が別列で重複保持されています。 どれか1系統だけを使い、混在させないでください。
  • 路肩拡幅の有無は Detection の列としては持ちません。 Video.road_type（拡幅／未拡幅）または Run のフォルダ別名で管理します。推論時の入力ミスがそのまま比較分析の誤りになります。
  • 「上書きする」オプションは過去データを削除します。 実行前に db/ のバックアップを取ってください。
  • Flask 開発サーバ（debug=True）で動作します。 localhost 前提の構成で、外部公開向けではありません。

設計思想としては、旧版は「1つの巨大な横持ちテーブルに全指標を書き込み、あとから好きな切り口で切り出す」方式です。列を足すだけで新指標を追加できる反面、どの列がどのキャリブレーションで計算されたかが行から追えません。新版 ADC Measurement 1.2 が計算を版付きで管理し、測定区間内の正式値と区間外の参考値を区別しているのは、まさにこの点への対応にあたります。
