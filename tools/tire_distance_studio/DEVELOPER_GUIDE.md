# 開発者ガイド

## 目的と設計方針

Tire Distance Studioは、既存の距離計算エンジンを直接改変せず、距離解析・可視化・アノテーション・再学習を安全に操作するためのTkinterフロントエンドです。UI固有の処理と推論処理を分け、長時間処理中も画面が固まりにくい構成にしています。

## ファイルの役割

| ファイル | 責務 |
|---|---|
| `app.py` | メイン画面、ページ遷移、高DPI表示、非同期処理、診断 |
| `annotation_editor.py` | 画像・動画抽出、bbox編集、既存YOLOラベル読込、保存 |
| `studio_utils.py` | 引用符付きパスの正規化、数値検証、不変設定オブジェクト |
| `MODEL_GUIDE.md` | 推論モデルと再学習ベースモデルの詳細説明 |
| `start_studio.bat` | 仮想環境を使った通常起動 |
| `check_environment.bat` | 構文検査とGUIなし環境診断 |

距離計算本体は同梱した `engine\tire_distance_engine.py` です。`app.py` の `import_engine()` がファイル位置から動的に読み込みます。

## 距離解析のデータフロー

1. Tkの入力値をメインスレッドで読む。
2. `AnalysisConfig.build()` がパス、拡張子、数値範囲を検証する。
3. 同名出力があれば日時付きの別名へ切り替える。
4. 検証済みの不変`AnalysisConfig`だけをワーカースレッドへ渡す。
5. エンジンの進捗は`queue.Queue`へ入れる。
6. `_poll_events()`がメインスレッドでログ、進捗、ダイアログを更新する。

Tkinterオブジェクトはスレッドセーフではありません。ワーカー内で`StringVar.get()`やウィジェット操作を追加しないでください。新しい設定を増やす場合も、開始メソッドで設定オブジェクトへコピーしてからワーカーへ渡します。

## 距離の座標系

画面側基準点は元画像の `(width / 2, height)` です。タイヤ側は初期設定でbbox下端中央です。

```text
画面下中央 = (width / 2, height)
タイヤ下端中央 = ((left + right) / 2, bottom)
distance_px = sqrt((x2 - x1)^2 + (y2 - y1)^2)
```

値は画像上のピクセル距離です。実距離へ変換するには、カメラ内部・外部パラメータ、路面平面、取り付け高さ等による校正が別途必要です。

## アノテーション座標

`IntegratedAnnotationEditor.samples[*]["boxes"]`は、常に元画像のピクセル座標です。表示時だけ次の変換を行います。

```text
canvas_x = image_x * display_scale + offset_x
canvas_y = image_y * display_scale + offset_y
image_x = (canvas_x - offset_x) / display_scale
image_y = (canvas_y - offset_y) / display_scale
```

そのため、4K表示、UI倍率変更、ウィンドウサイズ変更でも保存bboxは変化しません。YOLO保存時はエンジンが中心座標と幅・高さを0～1へ正規化します。

既存ラベル読込時は、数値でない行、NaN/Inf、負の幅・高さ、画像外だけの矩形を除外します。一部だけ画像外の矩形は画像境界へ収めます。入力全体に対して「最大枚数」を適用し、長い動画や大きなフォルダを無制限にメモリへ保持しない設計です。

## モデルの扱い

距離解析と自動アノテーションには、`Tire`または`Bicycle_Tires`相当のクラスを学習したモデルが必要です。標準の`models\best.pt`が推奨です。別モデルを選ぶとUIがUltralyticsからクラス名を読み、`tire`、`tyre`、`wheel`のいずれも確認できない場合は警告します。

`yolo26x.pt`、`yolo11x.pt`、`yolov8x.pt`はCOCO汎用モデルであり、直接のタイヤ距離解析用ではありません。これらはタイヤデータセットで再学習するための初期重みです。詳しくは`MODEL_GUIDE.md`を参照してください。

## エラー処理とデータ保護

- Windowsの「パスのコピー」で付く前後の引用符は`clean_path_text()`で除去します。
- 必須保存先の空欄をカレントフォルダとして扱わず、入力エラーにします。
- 既存CSVへ意図せず追記しないよう、同名出力は日時付きファイルへ分離します。
- 自動アノテーションは既存同名ファイルを上書きし得るため、開始前に確認します。
- 再学習は`replace_run=False`で既存runを保護し、Studio内の`models\best.pt`を自動置換しません。
- 完了通知側の例外でもイベント監視を継続します。

## 機能追加時のルール

- 公開・非公開を問わず、関数には「何を保証するか」を日本語docstringで記述する。
- 実装を読めば分かる逐語コメントではなく、座標系、スレッド境界、上書き防止など理由をコメントする。
- 入力検証は`studio_utils.py`へ集約し、UIイベント内で同じ検証を重複実装しない。
- エンジンへの引数追加は設定dataclass、UI取得、ワーカー呼出しの3か所を同時に更新する。
- Tkウィジェットはメインスレッド以外から触らない。
- 出力を上書きする変更は、明示確認または一意な新規ファイル名を使う。

## 回帰テスト

Studioフォルダで次を実行します。

```powershell
python -m py_compile app.py annotation_editor.py studio_utils.py
python app.py --check
```

手動確認では次を確認します。

1. 引用符付き動画パスを貼って読み込める。
2. 画像が縦横比を保ってキャンバス中央に表示される。
3. ドラッグしたbboxが緑で残り、Ctrl+S後のYOLOラベルが0～1に収まる。
4. 左右キーで移動し、既存ラベルを再読込できる。
5. 距離解析中にUIが応答し、完了後にCSVと動画が開ける。
6. 同じ出力名で再実行すると既存結果を変更せず別名になる。
7. `Ctrl`+`+` / `Ctrl`+`-` / `Ctrl`+`0`で表示倍率が変わる。

## 既知の制約

- 手動エディタは抽出画像をメモリに保持するため、最大枚数を大きくしすぎると使用メモリが増えます。
- 距離はピクセル値であり、カメラ校正なしではcm/mではありません。
- 自動ラベルは教師データの完成品ではありません。誤検出の削除と見逃しの追加が必要です。
- GPU推論・学習の速度と利用可能な`imgsz`/`batch`はGPUメモリに依存します。
