# モデル詳細ガイド

## 先に結論

| 作業 | 選ぶモデル | 理由 |
|---|---|---|
| タイヤ検出と距離解析 | `best.pt` | Tire専用クラスを持つ |
| 自動アノテーション | `best.pt` | Tire / Bicycle_Tiresのbboxを出せる |
| タイヤモデルの再学習開始点 | `yolo26x.pt` | 汎用特徴を初期重みに利用する |
| 比較実験の再学習開始点 | `yolo11x.pt`, `yolov8x.pt` | 世代間比較用 |

## best.pt

- ファイル: `models\best.pt`
- サイズ: 約130.4 MiB
- タスク: object detection
- クラス:
  - `0: Tire`
  - `1: Number_plate`
  - `2: Bicycle_Tires`

このプロジェクトのタイヤ検出用モデルです。距離解析ではクラス名に`tire`を含む検出を採用し、`Number_plate`は除外します。

`best.pt`は「モデルの種類を表す一般名」ではなく、ある学習runで最も良かった重みを保存するときの慣例的なファイル名です。別の学習runにも`best.pt`が存在し得るため、ファイル名だけでなく保存場所とクラス構成を確認する必要があります。

### 向いている用途

- 画面下中央からタイヤまでの距離測定
- Tire / Bicycle_Tiresの自動ラベル作成
- 既存性能の基準評価

### 注意

- Number_plateも学習クラスに含まれるため、低いconfではナンバープレート検出が増えることがあります。
- 距離エンジン側ではNumber_plateをタイヤから除外しますが、アノテーションは必ず目視確認してください。
- 新しい`best.pt`を作っても、既存ファイルをすぐ置換せず、別名で比較評価してください。

## yolo26x.pt

- ファイル: 配布物には含みません。再学習時に任意の保存場所から選択します。
- サイズ: 約113.2 MiB
- タスク: object detection
- クラス: COCO 80クラス

COCOのperson、bicycle、car、motorcycle、bus、truckなどを検出する汎用モデルです。`Tire`クラスはありません。そのままタイヤ距離解析へ使うモデルではありません。

このUIではタイヤデータセットを再学習する際の初期重みとして推奨します。`x`は大規模モデルを示し、一般に小型モデルより精度余地がある一方、GPUメモリ、学習時間、推論時間が増えます。

元エンジンには、環境のUltralytics版とYOLO26重みの互換性を補う処理があります。ログに「YOLO26互換パッチを適用しました」と表示される場合があります。

## yolo11x.pt

- ファイル: 配布物には含みません。比較実験時に別途用意します。
- サイズ: 約109.3 MiB
- タスク: object detection
- クラス: COCO 80クラス

YOLO11系の大規模汎用モデルです。Tire専用クラスを持たないため、直接の距離解析には使いません。YOLO26と同じデータ分割・学習条件で再学習し、速度や精度を比較する用途に使えます。

## yolov8x.pt

- ファイル: 配布物には含みません。比較実験時に別途用意します。
- サイズ: 約130.5 MiB
- タスク: object detection
- クラス: COCO 80クラス

YOLOv8系の大規模汎用モデルです。既存研究や以前の実験との比較基準として有用ですが、これもTire専用クラスを持ちません。

## 検出モデルとベースモデルの違い

検出モデルは、現在の目的クラスを学習済みで、そのまま推論に使える重みです。このプロジェクトでは`best.pt`が該当します。

ベースモデルは、新しい目的クラスを再学習するときの初期値です。COCOの多様な物体から得た画像特徴を引き継ぎ、ゼロから学習するより少ないデータで収束しやすくします。`yolo26x.pt`などが該当します。

COCO汎用モデルを距離解析へ直接指定しても、クラス名にTireがないためタイヤとして採用されません。

## confの決め方

confは「この検出を結果として採用するか」のしきい値です。

1. `0.10`で短い代表動画を処理する
2. 誤検出が多ければ`0.20`
3. まだ多ければ`0.30`
4. 見逃しが多ければ`0.05`
5. 代表条件ごとに件数と目視結果を記録する

自動アノテーションでは、見逃しを後から追加する作業と誤検出を削除する作業のどちらが楽かを考えて決めます。一般には少し低めのconfで候補を広く出し、目視で削除する方法が向いています。

## imgszの決め方

タイヤは画面内で小さくなりやすいため、imgszの影響を受けます。

- `640`: ベースライン
- `960`: 遠方や小さいタイヤの改善候補
- `1280`: 高解像度入力向け。GPU負荷が大きい

入力動画自体の解像度やブレが不足している場合、imgszだけ上げても情報は増えません。

## 再学習モデルの評価

学習lossだけで採用を決めず、未学習のval/test映像で次を比較してください。

- Tireのprecision: 検出したものの正しさ
- Tireのrecall: 実際のタイヤを拾えた割合
- 小さいタイヤ、遮蔽、夜間、雨天での見逃し
- Number_plateや路面模様への誤検出
- 距離線が意図したタイヤへ結ばれる割合
- 実運用GPUでの処理速度

モデルを置き換える前に、旧モデル、候補モデル、評価条件、conf、imgsz、評価結果を記録してください。

## UIのモデル安全確認

標準の`models\best.pt`以外を距離解析または自動アノテーションへ指定すると、UIはモデルのクラス名を読み取ります。クラス名に`tire`、`tyre`、`wheel`のいずれかがあればタイヤ用候補として続行します。確認できない場合は、検出クラスを表示して続行確認を求めます。

これはファイル名が`best.pt`というだけでタイヤモデルだと判断しないための保護です。再学習runごとに同名の`best.pt`ができるため、採用時はクラス構成、評価指標、代表動画での可視化を必ず確認してください。
